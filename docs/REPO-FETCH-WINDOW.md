# 仓库查询时间范围

本轮本地实现按用户明确指定的规则：使用仓库最近推送时间，默认近 7 天，可选近 3 天、7 天、15 天、30 天或全部。时间范围是从刷新开始时往前计算连续的 24 小时，边界时刻计入。

“项目总览”和“等我处理”的刷新按钮旁均有时间范围选择器；切换后统一保存到本机并立即刷新当前页面，另一个页面下一次刷新使用同一个设置。也可在“设置 → 仓库查询范围”保存。自动发现和手动关注的仓库都应用该规则。未推送过的仓库只在“全部仓库”下查询。

“等我处理”的时间范围限制仓库扫描。直接指派给你、请求你 review、提及你的事项仍查询；手动配置的状态文档、本机待办与本地分支继续按各自已有设置检查。仅更新 Issue、PR 或 Command Center 不会让仓库的推送时间变新；要核对这类历史项目，应选择更长时间范围或全部。项目总览的“陈旧天数”继续用于对已查询到的项目分组。

## 查询与缓存行为

自动仓库列表按 GitHub 的 PUSHED_AT DESC 查询，首次读取包括推送时间；翻到范围外的仓库便停止分页，在读取 PR、Issue、CI 与 Command Center 之前排除旧仓库。手动关注列表先用批量元数据查询取得推送时间，范围内仓库才读取详情。仓库数量上限针对时间范围内的候选仓库；选择“全部”沿用完整范围和原数量上限。

全局设置持久化字段为 `repoFetchWindow`，值为 `3d`、`7d`、`15d`、`30d` 或 `all`。旧设置只补此字段的默认值，不重置关注仓库、认证、工具、规则或本机数据。两个页面的刷新键包含该字段；缓存记录其查询范围。更换范围会失效原刷新 TTL，清理原范围的仓库扫描结果，并保留等我处理的直接请求与本机来源。配额冷却仍按认证身份生效，切换范围不会绕过冷却。

时间与范围判断、可选值、持久化字段、IPC 和界面选择器在两页之间共用。当前低层加载 API 省略参数时保留原完整范围行为；桌面程序与 CLI 均显式传入共享设置。
