# 项目总览：Command Center 进度看板

2026-10-12 本地源码候选。目标是让用户在项目总览直接看到各项目当前阶段、状态、门禁、下一动作和阶段记录。没有自动更新项目控制面，没有新增 GitHub 写入，也没有打包、安装或正式 Phase Accept。

## 交互与数据口径

- 默认展示项目卡片，可按实现中、验证 / 待验收、阻塞和待核对筛选。共用上一轮排序与时间实现；默认最近活动倒序，各页的排序选择继续分别保存。
- 当前状态从 Command Center 唯一的当前摘要读取。支持标准 One-glance / 一眼状态表格、当前一句话状态、明确的旧版 Section 1。阶段索引与例外 / 阻塞记录可展开。较长内容在卡片上压缩显示，详情保留完整读取文本。
- 来源入口、GitHub 更新时间、读取时间，以及原文声明的更新日期分别保留。未知状态显示原文和核对提示。历史 details、代码、示例和历史小节不作为当前字段；引用可作为摘要原文展示，不用作状态字段。
- 只读展示总控台的记录。Issue 关闭、PR 合并、CI 通过不推导 Phase Accept，也不计算没有依据的完成百分比。`done` / `accepted` 显示为「记录完成」，阶段索引明确说明未逐项核验 PHASE ACCEPT。
- 未发现开放总控台、多个候选、候选查询不完整、摘要格式不支持、缺字段与读取失败分别呈现。失败时保留同一身份的上次记录，标为缓存并计入待核对。成功读取确认不存在或出现多个候选时，不保留旧记录作为当前状态。
- 原仓库 CI、PR 等待、停滞、空仓、陈旧和归档规则保持，提醒移到卡片的「仓库状态」。这些提醒的数量与阶段状态分开表达。

## 实现边界

现有概览批量查询同时读取标签候选与两种标题候选。每批 3 个仓库、并发上限 6 不变；英文 / 中文标题搜索各在批次级执行一次，每种最多 18 个候选。每仓标签候选最多 4 个。结果按明确的 repository identity 归属，不能把不同仓库相同 Issue 序号混到一起。候选存在分页、数据不完整或来源不一致时不自动选择。

Markdown 使用既有生产依赖 marked 18.1.0 Lexer 解析，源码不渲染远端 HTML。仅提供 HTTPS GitHub 链接。正文上限 80,000 字符；阶段索引和例外 / 阻塞各显示最多 30 项，超过时提示查看源 Issue。上限不会被当作全量完成。

读取复用身份隔离、TaskScope、取消、速率冷却和一分钟成功缓存。缓存契约升级到 version 2，旧缓存或无效总控台数据不会跳过本轮读取；没有新后台线程或定时轮询。失败读取不产生成功 TTL。
