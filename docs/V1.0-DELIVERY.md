## 2. 已实现功能（对照 #35）

### A. 统一任务与交办 — 已实现并验证

- 新增「任务」页并作为默认入口。可从自然语言目标创建任务，选择实际工作目录，可选关联仓库，选择 Codex / Claude Code / 自动、授权范围和优先级。
- 交办默认值：记住上次使用的工作目录、仓库、Agent、授权范围和优先级；常用目录可直接从下拉选择，切换目录会反推关联仓库；Agent / 授权 / 优先级收进「高级选项」，主按钮为「创建并开始」。
- 任务先进入「待确认范围」，详情显示目标、目录、Agent、授权、轮次与限额；用户点「确认范围并开始」后才执行。
- 灵感、待办保持独立，不会自动执行；两处都新增「交给 AI」，会带原文和仓库进入任务页，仍需用户确认范围。
- 任务卡集中记录状态、当前 Agent、轮次、下一动作、等待原因、决定、成果和证据。

### B. Windows 本地 Agent 与会话接续 — 已实现并真实执行

- **Codex**：`codex exec --json`；支持 `resume <thread>`；真实完成文件创建、命令检查、结构化回执和反馈返修。
- **Claude Code**：`claude -p --output-format stream-json --verbose`；支持 `--resume`；prompt 通过 stdin 传入，不进入命令行。
- 两者都有超时、进程树回收、退出码/ stderr 诊断、日志尾部和真实会话 ID。
- **本机已有 Claude 会话**：扫描 `~/.claude/projects`，按实际目录和 GitHub origin 归组，显示来源（本机/Arckeep），可读最近文字记录并在原目录恢复。实测发现 74 条本机会话、26 个项目，并恢复了一条并非 Arckeep 启动的会话。
- **FB-003 终端启动**：根因是 Windows Terminal 的 App Execution Alias 对 Node `existsSync` 返回 `EACCES`，旧逻辑永远找不到 `wt.exe`。已改为识别 App Execution Alias，并保留 Windows Terminal 启动失败时回退 PowerShell 的路径。真实启动后用 `AppActivate` 验证成功。
- **人工接管**：任务详情新增「接管」，在 Windows Terminal（不可用时回退 PowerShell）打开任务工作目录；Claude/Codex 已有会话时直接 `resume`。等待中的任务先暂停，运行中/排队中拒绝接管。真实点击后观察到 Windows Terminal 与 `codex resume 01a1a5d1-...` 进程，说明不是只打开一个空终端。

### C. 事件驱动、后台续办与多任务 — 已实现并真实验证

- 事件来源：定时、GitHub PR/CI、用户决定。
- GitHub 等待轮询 PR 最新 head 的 check runs 与 legacy commit status；pending/success/failure 聚合，支持限流退避与 401/404 提示。
- 事件触发后把最新事实写入续办 prompt，要求 Agent 先核对再继续；暂停任务不会被事件自动恢复。

## 4. 用户如何使用

### 安装

1. 取得 `Arckeep-Setup-1.0.0.exe` 或 `Arckeep-1.0.0-portable.exe`；核对 `SHA256SUMS.txt`。
2. 运行安装包（未签名，SmartScreen 可能提示）或双击 portable。
3. 打开「设置」：确认版本 1.0.0；如需要 GitHub，使用已登录的 `gh` 或保存只读 PAT；在「AI 任务执行」确认 Codex/Claude Code 已检测到。

### 交办

1. 打开「任务」→「交办新任务」，写目标，选择工作目录（可选关联仓库）。Agent、授权范围和优先级在「高级选项」里，默认沿用上次设置。
2. 需要时调整 Agent、授权范围和优先级；建议先「仅创建」。
3. 在详情核对执行范围，点「确认范围并开始」。

### 查看 / 决定 / 验收

- 进行中看执行轮次、实时进度和日志。
- 等待事件时看等待类型、最近检查、超时时间；可「立即核对」。
- 需要你决定时在任务页顶部或详情选择选项；回复会回到原任务。
- 结束后看产物、检查、未验证事项；点「验收通过」，或填写反馈后「提交修改」。

### 暂停 / 继续 / 取消

- 运行中、排队中、等待中或等我决定时可暂停；暂停不会因新事件自动恢复。
- 需要手工处理时点「接管」，会在外部终端打开任务目录并尽量恢复原会话；等待中的任务会先暂停。
- 暂停后可继续；排队任务轮到时才执行。
- 任务可取消；运行中取消会中止当前进程。

### 备份 / 恢复

- 从托盘「退出」后复制 `%APPDATA%\Arckeep\`。
- 任务索引 `tasks.json`；运行日志 `task-runs\`；原有 `todos.jsonl`、`ideas.json`、`prompts.json`、`settings.json` 不变。
- 恢复时先退出应用，再把数据目录放回；任务状态会按持久化记录恢复，运行中的残留轮次会标记中断并要求核对。

## 5. 已知限制

- Windows x64；无签名、无自动更新。
- 需要本机已安装并登录 Codex / Claude Code CLI；Arckeep 不代装、不代管凭据。
- 完全自主模式不是系统级沙箱；详见安全边界。
- GitHub 事件需要 `gh` 或 PAT 的读取与 checks 权限；分类/等待状态可能漏判。
- Agent 写入非 ASCII 内容时存在外部 CLI 的编码风险；任务协议提示 UTF-8，但不能强制外部 CLI 行为。
- 等待超时、网络失败、进程被系统结束时任务会停止并保留现场，不会自动猜测或重做有副作用的写入。
- 本机 Claude 会话只读取最近一段文字，工具输入/输出全文不展示；不上传或复制聊天内容。
- PR #36 未合并，tag/Release 未创建；`main` 仍是旧版本，安装包来自 PR merge ref。
