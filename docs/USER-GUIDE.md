# Arckeep 用户说明书

Arckeep 把即时灵感、自己记下的待办、常用提示词、从 GitHub 读取的协作信号、Claude CLI 外部终端入口和常用工具放在一个 Windows 桌面工作台里。它帮助你捕捉、整理和查看信息；GitHub 分类和项目提醒是供你核对的线索，最终判断与后续操作仍由你完成。

版本说明：本机已更新为 0.1.6 本地试用版，包含排序、APO 快捷评论、Command Center 看板、仓库推送时间范围配置，以及 Claude CLI 外部终端入口与会话查看。本次是本机试用更新，尚未正式发行。

可以先用待办和工具架，再连接 GitHub。最小的一次体验是：按 **Ctrl+Alt+Space**，输入 `确认工具架提示词 #Dylan5237/arckeep !等我` 并回车；在**待办**找到这件事，处理后勾选完成；再到**工具架**复制 APO 提示词，粘贴到目标项目的 Coding Agent 会话。这三步分别对应记事、管理任务和调用常用入口。

## 什么时候打开哪一页

| 页面 | 适合什么时候打开 | 你会得到什么 |
| --- | --- | --- |
| **快速捕获** | 正在使用其他应用时，想到一件要做的事或一条灵感 | 切换「待办」或「灵感」模式，分别保存为本地待办或灵感 |
| **灵感** | 想回看、补充或删除尚未决定要不要执行的想法 | 独立的灵感列表，可新建、查看、编辑和删除 |
| **提示词库** | 想保存、搜索并复用常用提示词 | 按标题、正文和标签搜索，置顶常用条目，直接复制原文 |
| **等我处理** | 想集中检查别人请求你处理的 GitHub 事项，以及自己的「等我」待办或本地未推送分支 | 按规则汇总并标出来源、理由；先显示上次结果，再按需自动更新，也可手动刷新 |
| **项目总览** | 想看各项目推进到哪一步、卡在哪里 | Command Center 进度看板、阶段索引、门禁与下一动作，以及仓库提醒 |
| **Claude 会话** | 想回到某个项目目录中的 Claude CLI 终端，或查看 Arckeep 启动的会话记录 | 按项目和实际工作目录查看会话，可恢复会话并阅读最近的文字记录 |
| **待办** | 想查看、筛选、编辑或完成自己记录的事情 | 未完成待办、折叠的已完成项和删除撤销 |
| **工具架** | 想打开常用仓库/文件夹、复制模板，或运行自己配置的命令 | 可重复使用的本机动作入口 |
| **设置** | 首次使用、认证或热键异常、要调整数据来源和规则时 | GitHub 认证、关注仓库、等我处理来源、本地仓目录、总览阈值和工具架配置 |

## 首次使用：先连上数据来源

1. 在主窗口打开**设置**，先看 Arckeep 显示的应用版本。若已用 GitHub CLI（gh）登录，Arckeep 会优先使用该登录；否则可保存具备目标仓库读取权限的 Personal Access Token（PAT），再点**测试连接**。PAT 输入框不会回显内容；应用通过 Windows 的安全存储加密保存。若系统安全存储不可用，应用会拒绝明文保存。
2. 在**关注仓库**中添加 owner/repo。关注列表用于指定关注范围；项目总览在列表为空时采用自动模式，收录你有写权限的仓库，不包括只有 watch 权限的仓库。等我处理也有自己的来源开关和范围设置。
3. 若要查看本地未推送分支，在设置的**等我处理**卡片中启用「本地没推送的分支」，并在「本地仓目录」里每行填写一个 Git 仓库目录本身（例如 D:\work\demo），不要填它的父目录。电脑上还需要能从 PATH 找到 git。这里只列出已设置 upstream、且本地领先远端的分支。
4. 默认全局热键是 **Ctrl+Alt+Space**。首次使用时试按一次；若与其他程序冲突，到设置里换一个当前未占用的组合键并保存。

## 每天的最小流程

在任意应用里想到一件事，按 **Ctrl+Alt+Space**，先选「待办」或「灵感」再记录：明确要做的事记为待办，暂时只是想法的内容记为灵感。需要检查别人交给你的事项时打开**等我处理**，逐条确认 GitHub 原文或本地来源；想看仓库层面的提醒时打开**项目总览**；要继续某个项目里的 Claude 工作，从项目卡片启动后到**Claude 会话**查看记录；处理个人任务则到**待办**勾选完成。需要重复打开的路径、提示词或本机命令，可以从**工具架**启动。

### 快速捕获、待办与灵感

按 Ctrl+Alt+Space 打开快速捕获后，可在「待办」与「灵感」之间切换。窗口会恢复上次未保存的正文、仓库和模式；按 Esc 或点到窗口外会关闭窗口，并保留草稿及当前模式。

选择「待办」时，正文仍是最多 500 字符的单行文本，并支持以下快捷写法：

- #owner/repo：提取为仓库标签，不留在待办正文中。
- #repo：只有在已知仓库中能唯一匹配时才提取；名称不唯一或未知时会保留为普通正文。
- !等我：提取为「等我」标记，不留在正文中。也可以直接勾选窗口里的「等我」并填写仓库栏。

待办模式下按 Enter 保存并关闭窗口。成功保存后会短暂提示。

选择「灵感」时，正文可多行，最多 10,000 字符，可选填写 owner/repo。按 Enter 保存并关闭窗口；Shift+Enter 换行。灵感正文不会解析 # 仓库或 !等我。多行或超过 500 字符的灵感不能切换为待办，以免切换时丢失内容。

#### 待办

待办页默认先显示未完成项。顶部筛选器可看全部仓库、无仓库项或某个仓库；勾选复选框可完成或重新打开一项。点**编辑**可修改正文、仓库标签和「等我」标记，保存或取消后返回列表。已完成项收在可折叠分组里。删除后页面会短暂显示**撤销**；错删时立即点它恢复。

#### 灵感

**灵感**页与待办列表、等我处理互相独立。你可以新建、查看、编辑或删除灵感；删除前会显示内容摘要并要求确认，删除后没有撤销入口。灵感正文最多 10,000 字符，可选填写 owner/repo，适合保存暂时没有明确下一步的念头。灵感保存在本机，不需要 GitHub 认证；它不会自动变成待办，也不会进入等我处理。要执行时，请另外新建一条待办。当前没有附件、AI 整理或云同步。

### 阅读「等我处理」和「项目总览」

两个页面都提供**排序**，默认按最近活动时间倒序，新的在上面；也可以选择从旧到新或按仓库名称排序。选择分别保存在本机，刷新和切换页面后会保留。等我处理按事项的 GitHub 更新或本机事项更新时间排序；项目总览按默认分支提交、Issue/PR 活动、推送和仓库创建时间中最新的一项排序，陈旧和归档分组内也沿用所选顺序。

等我处理的仓库名和 Issue/PR 序号加粗显示。等待时长从触发原因起算，不足一天显示小时或分钟，少于一分钟显示「刚刚」；缺少可靠时间时会注明估算或显示「不足 1 天」。排序的最近活动时间与等待开始时间可能不同。

明确请求你按 APO 评论 **FREEZE ACK**、**EXCEPTION ACCEPT** 或 **PHASE ACCEPT** 时，事项下会出现同名快捷按钮，并列出将回复的仓库和序号。点击按钮就是以当前 GitHub 登录账号发送这句原文；请先核对事项内容和评论目标。这三类 APO 决定只发送到对应的 Phase/架构例外 Issue。请求可以来自 PR，只有明确指出目标 Issue 时才提供按钮；不会把决定评论到实现 PR。请求指定其他 Issue 时，会发送到该目标。

提交前会重新核对账号、请求和目标；请求已变化、已回复或目标已关闭时会阻止评论并提示刷新。请求中的示例、引用、带前置条件的内容，以及目标不明确、处置人身份无法核对或评论历史不足以判断的内容不显示快捷按钮。已知处置人与当前账号不符时也会阻止提交。需要附理由或额外内容的退回/拒绝意见仍通过 GitHub 编写。快捷评论需要目标仓库的评论写权限；fine-grained PAT 需要目标仓库的 Issues 写权限，只有读取权限时仍可刷新列表，但无法发送评论。

成功后按钮显示「已评论」并禁用。网络中断或超时导致结果无法确认时，按钮会停止重复发送；点**核对评论结果**只重新读取 GitHub，不重发评论。尚未核实时可点旁边的仓库/序号链接查看原记录。发送记录保存在本机，重启后继续防止重复提交。GraphQL 配额耗尽只影响列表读取；快捷评论通过 GitHub REST API 完成，仍受 GitHub 的权限和 REST 速率限制约束。

两个页面会先显示本机已有的结果，刷新期间列表继续可用。刚成功刷新过时，一分钟内切换回来会复用 GitHub 结果；「等我处理」仍会重新核对本机待办和本地分支。点击**刷新**会主动查询最新数据。列表上的「上次刷新」标明数据时间；网络失败时保留旧结果并显示错误，因此旧列表不代表已获取最新信息。

刷新按钮旁的时间范围按**仓库最近推送时间**筛选，默认**近 7 天**，可以选择**近 3 天、7 天、15 天、30 天或全部仓库**。两个页面共用这一设置，切换后当前页立即刷新，另一个页面下次刷新采用相同范围；也可在**设置 → 仓库查询范围**保存。范围按刷新开始时往前的连续 24 小时计算，边界计入。自动发现和手动关注的仓库都受此范围限制；仅更新 Issue、PR 或 Command Center 不算推送，需要查看这类历史项目时扩大范围或选全部。从未推送过的仓库只在全部范围中出现。

时间范围只限制仓库扫描。“等我处理”仍检查直接指派给你、请求你 review、提及你的事项，以及手动配置的状态文档、本机待办和本地分支。改变范围后，原范围的仓库扫描缓存会清理；读取元数据失败会显示错误并保留对应范围的上次结果，配额冷却不会被切换范围绕过。项目总览的陈旧天数继续决定已查询仓库的分组。

**等我处理**可合并 GitHub 上指派给你、请求你 review、提及你、符合人工动作规则的 Issue/PR，以及符合设置规则的状态文档；本机来源还可以包括带「等我」的待办和未推送分支。明确度较高的事项进入主列表；较弱的提及线索收在「可能相关」中。每条会显示分类理由和来源，分类是规则推断，可能漏掉或误判。页面默认读取 GitHub 信息，只有你点击快捷评论按钮后才会发送对应评论；程序不会自行合并 PR、关闭 Issue 或修改阶段状态。**延后**可选 1、3、7 天；**忽略这一条**只隐藏该条，**不看 owner/repo 这个仓库**隐藏整个仓库；可用「显示已忽略」或相应的**恢复**入口找回来。这些整理状态保存在本机。

**项目总览**现在提供项目进度看板，默认按最近活动时间倒序。每张卡片展示该项目 Command Center 的当前阶段、明确状态、门禁 / 阻塞和下一动作；点**阶段与总控台详情**展开阶段索引、原文摘要、结果和例外记录。上方可筛选实现中、验证 / 待验收、阻塞和待核对，筛选和排序都在本机完成，不会重新请求 GitHub。卡片下方的 **Command Center #序号**打开原 Issue，旁边分别标明 GitHub 更新时间和读取时间。

看板读取开放的、带 type:command-center 标签或规范标题的 Issue。标准「一眼状态」表格、当前一句话状态和旧版明确的 Section 1 摘要可展示；不支持的格式提供原 Issue 入口。未找到、多个候选、字段缺失、状态不明确或读取失败会分别提示。网络失败时保留并标明**缓存**，缓存记录不计入当前状态筛选统计。缺少阶段信息不会按 PR 数量生成进度百分比；PR 合并、CI 通过或 Issue 关闭也不会自动显示 Phase 验收通过。阶段索引的「记录完成」仅表示总控台这样记录，Arckeep 未逐项核验 PHASE ACCEPT。总控台的编辑与维护仍在 GitHub 完成。

每张卡片的**仓库状态**保留原有仓库提醒。默认规则中，「卡住」可能表示默认分支 CI 失败，或有尚未获得批准、也没有明确被要求修改的非草稿 PR，自创建起等待至少 3 天；「停滞」表示默认分支提交和 Issue/PR 活动都超过 7 天没有更新；「空仓」表示没有提交或仓库体积为零。提醒链接会打开 GitHub 对应仓库或 PR。「有仓库提醒」只汇总活跃仓库的读取错误及卡住、停滞、空仓线索，不含陈旧或已归档仓库，也不代表阶段门禁的数量。

默认最近活动超过 30 天的仓库会收进可折叠的**陈旧**分组；默认不显示已归档仓库，可在设置中开启。关注列表为空时，总览自动扫描你有写权限的仓库；有关注列表时按关注范围读取。可以在设置里调整停滞、review 等待和陈旧天数。GitHub 数据或分类有疑问时，点仓库名或提醒链接核对原记录。

### 从项目总览启动 Claude

先在 Windows 安装并登录 Claude Code CLI，并确认命令行能找到 `claude`。在**项目总览**对应的项目卡片上点**使用 Claude 工作**；首次使用时选择这个项目的本地仓库目录。Arckeep 会读取该目录的 GitHub `origin` 并核对仓库标识，匹配后才启动。后续启动会沿用该项目保存的工作目录；要切换到另一个 clone 或 worktree，可在**Claude 会话**页选中项目后点**更换工作目录**。

Claude 在独立的 Windows Terminal 窗口中运行；系统没有 Windows Terminal 时使用 PowerShell。Arckeep 不在主窗口内嵌终端。启动提示表示 Arckeep 已向外部终端发送请求，请在终端确认 Claude 已就绪；如果 CLI 无法启动，检查终端窗口中的错误。Claude 退出后专用终端保持打开，标题会标记会话已结束，方便查看错误或自行关闭。Arckeep 启动 Windows Terminal 时会请求使用应用标题，以便识别并聚焦会话窗口。重复点击项目入口会尝试把同一仓库、同一工作目录中已经打开的会话窗口带到前台；同一工作目录的启动决策会串行处理。若标题匹配不到已打开的终端，Arckeep 可能把它当作未运行，因此在 10 秒启动缓冲期后再次启动可能另开窗口；遇到这种情况请先手动检查终端。点击某条会话的**恢复**会以该会话 ID 运行 `claude --resume`；若同一工作目录已有另一个会话正在启动或运行，Arckeep 会提示冲突，不会静默改为恢复其他会话。不同 worktree 路径会成为不同会话，Viewer 按项目归组并逐条显示实际目录，记录不会串到同仓库的其他 worktree。

**Claude 会话**页只显示由 Arckeep 建立索引的会话，不会扫描或导入其他方式启动的 Claude 会话。选择一条记录后可阅读 Claude 本地会话文件中最近的文字消息；工具调用只显示工具名称，不显示工具输入或输出。终端交互仍在 Claude 的外部窗口完成。会话索引保存在 `%APPDATA%\Arckeep\claude-sessions.json`，聊天正文仍由 Claude 保存在其本地数据目录中；Arckeep 按会话工作目录和 ID 读取记录，不上传或复制聊天内容。

### 提示词库：快速找到并复制

打开**提示词库**，点**新增提示词**，填写一个便于识别的标题和完整正文，可选填写标签并置顶。保存后，输入标题、正文中的关键词或标签即可即时筛选，搜索不需要 GitHub 连接。置顶条目排在前面，每条都有直接复制入口；点击标题可查看完整正文。

标签用中文或英文逗号分隔，也可从「全部标签」下拉框筛选。多个搜索关键词需同时匹配，双引号可用于完整词组；在提示词库中按 Ctrl+F 可直接聚焦搜索框。

点击**复制**只复制提示词正文，保留原始换行、缩进和空白，不附加标题或标签，也不替换模板变量。看到**已复制**后，即可粘贴到目标 Agent、编辑器或聊天中使用。复制失败时页面会显示错误。

提示词可编辑，也可确认后删除。每条标题最多 120 个字符，正文最多 50,000 个字符，最多 12 个标签，每个标签最多 30 个字符。提示词保存在本机的 prompts.json，不依赖认证；当前没有云同步或自动执行功能。未保存的编辑草稿在切换模块后保留于本次运行，重新进入可继续编辑；退出应用后不保留该临时草稿。

提示词库从 0.1.2 本地试用版开始提供；本机当前已安装 0.1.6。之前的 0.1.1 不包含该模块。

### 工具架：四类动作

工具架首次配置默认有四个示例动作：打开 GitHub 仓库、在编辑器中打开文件夹、复制 APO 初始化提示词、复制派工说明。工具架支持以下四种动作类型；默认示例没有运行命令卡，按需要自行配置：

- **打开链接**：在浏览器中打开配置的地址。
- **打开文件夹**：在资源管理器或配置的编辑器中打开选择的目录。
- **运行命令**：可使用 cmd、PowerShell 或 Git Bash。根据参数配置选择目录、仓库或填写文本；运行前会显示预览并要求确认。预演命令本身也可能写文件或产生其他副作用，确认前应检查命令和工作目录；运行中可中止，完成后可复制输出。
- **复制模板**：把模板文本复制到剪贴板，可带参数，也可不带参数。

本批修改后的 **APO 项目初始化**属于「复制模板」，无参数，复制的固定文本是：

> 使用 https://github.com/Dylan5237/agent-project-ops 初始化当前项目。

复制后，请先在目标项目里打开你指定的 Coding Agent 会话，再粘贴并由该 Agent 实际执行初始化。Arckeep 只复制提示词，不会调用 Agent 或初始化项目。

工具架 JSON 在**设置 → 工具架**中编辑。**填入示例**只会填进编辑框，点**保存**后才生效；**导入**也是先载入编辑框，仍需保存；**导出**可把当前编辑内容另存为文件。已有个人动作时不要用示例覆盖整架：保留现有 actions，只替换 id 为 apo-init 的动作对象。新对象如下：

~~~json
{
  "id": "apo-init",
  "title": "APO 项目初始化",
  "description": "复制提示词，在目标项目的 Coding Agent 会话中粘贴使用。",
  "confirmLabel": "复制初始化提示词",
  "type": "template",
  "text": "使用 https://github.com/Dylan5237/agent-project-ops 初始化当前项目。"
}
~~~

新源码只会在旧动作与旧默认对象完全一致时自动替换它；自定义过的旧动作请按此方式手动更新。

## 常见问题

- **等我处理没有内容**：确认页面已刷新、GitHub 认证有效，并在设置检查需要的来源开关和仓库范围。「可能相关」需要展开查看；速率限制时页面会提示重置时间，并保留上次读取的列表。
- **项目总览为空**：先测试连接。自动模式只包含有写权限的仓库；只有 watch 权限的仓库不会出现。也可将目标仓库加入关注列表。
- **待办看起来消失了**：先把筛选器切回「全部仓库」，再检查「无仓库」或对应仓库筛选；删除后的撤销入口只短暂显示。
- **灵感保存失败**：先按页面提示检查正文和 owner/repo 格式；失败后输入内容会保留，可修改后重试。若提示数据文件损坏或版本不支持，应用会保留原文件并停止修改灵感数据，其他模块仍可使用。先退出应用并备份数据目录，再处理文件问题。
- **热键无反应**：看主窗口提示或托盘状态；若显示热键不可用，在设置里改成未占用的组合键并保存。
- **本地分支报错或没有结果**：目录必须是 Git 仓库本身，且 git 可运行；还要启用本地分支来源。只列出有 upstream 且领先远端的分支。
- **工具架 JSON 无法保存或工具架为空**：按页面报出的行号修正 JSON；或点「填入示例」后检查并保存。导入文件不会自动保存。
- **GitHub 认证报错**：检查设置里显示的当前认证来源。Arckeep 优先采用 gh 登录；若 CLI 使用了错误账号或权限，可先切换 gh 登录，再测试。PAT 无效或权限不足时，请换用有目标仓库读取权限的 PAT。网络中断或 API 限流时，稍后再刷新。

## 窗口、数据与本次候选版说明

关闭主窗口只会隐藏到系统托盘，Arckeep 仍在运行；双击托盘图标或用菜单可重新打开。要真正退出，请从托盘菜单选择**退出**。设置里的「启动时隐藏主窗口」只影响启动后的显示方式。

选择退出后，应用立即停止接收新操作，取消 GitHub 刷新、认证查询和本地 Git 查询，并回收正在运行的工具命令与预演进程。正常情况下会等待清理完成后退出；整个退出流程最多等待 15 秒。通过工具架单独打开的浏览器、编辑器或文件夹继续由你使用。

退出时会尝试保存快速捕获窗口中尚未提交的草稿；已成功创建的待办或灵感不会再写回草稿。若窗口无法及时响应，会保留最近已保存的草稿。清理失败或超时时，应用会记录 %APPDATA%\Arckeep\lifecycle-errors.jsonl，内容包括时间、失败阶段及尚未结束的任务/资源数量，不记录 token、命令正文或命令输出。遇到退出异常时可提供这份诊断文件用于排查。

Windows 用户数据位于 %APPDATA%\Arckeep\，包括 settings.json、追加记录式的 todos.jsonl、独立的 ideas.json、提示词库的 prompts.json、capture-draft.json，以及 GitHub 读取缓存、本地隐藏/延后状态文件和快捷评论结果记录 apo-comment-receipts.json。灵感、待办和提示词保存在各自的数据文件中。GitHub PAT 以安全存储加密值写入设置；其余个人待办、灵感、提示词和路径信息保存在本机。应用没有云端同步。备份前从托盘**退出**，再复制整个 Arckeep 数据目录；不要把含个人设置的目录随意分享。

本说明适用于 **0.1.6 本地试用版**。较早版本的安装包仍带旧版 APO 初始化动作；如果保存的动作与原始默认对象完全一致，新版本会在加载设置时只升级该动作，保留其他工具。用户已自定义过工具架时，按上文只替换 apo-init 对象即可。本地试用版面向 Windows x64，尚未正式发布，没有自动更新。

0.1.6 保留灵感页、提示词库、快速捕获双模式、APO 提示词、刷新优化与退出生命周期处理、项目进度看板、两页排序、APO 快捷评论和共用的仓库推送时间范围，并加入 Claude CLI 外部终端启动与会话查看。升级后可在设置中确认版本为 0.1.6。GitHub 缓存与当前有效凭据绑定，切换账号或失去认证后不会继续使用旧身份的成功缓存。
